# 纯数据 → 模板 → 填写 的方法（deskpilot-oa-fill）

本文件是「智能体如何产出与校验纯数据、并映射到页面」的可复用方法。不是一次性步骤清单。

## 流程顺序（每次填单前固定做这三步）

1. **校验纯数据**（离线，不连浏览器）：`node oa-data-validate.mjs --template <模板> --data <纯数据>`。
   - 目的：OA 会因空闲超时清空整张未保存表单（坑 #3），所以填单前必须先把数据校验齐全，否则填一半因缺必填失败、又得整单重来。
   - 校验器拦三类：必填字段缺失 / 占位值未替换（`示例：`、`（待填写`）/ 纯数据泄露选择器。
   - 退出码 0=通过，2=失败并列出缺失清单。填单前必须 0。
   - **用户交来的数据通常不全，这是常态**：校验器会输出一份给人看的报告（状态 / 缺口清单含"怎么做" / 可选未填项 / 下一步），把它原样转给用户；不要只回一句"校验失败"或错误码。

2. **映射**（智能体据模板做，用户不接触）：把纯数据的业务字段名，对照模板 `field_map` 的 `type`，分发到引擎的四类动作（text/select/browser/radio）+ 明细列。映射产物就是「模板 + 纯数据」这两个 JSON 交给 `oa-fill-engine.mjs`，映射本身不落一个中间文件 —— 引擎就地按 type 分发。

3. **执行 + 回读**：引擎跑完后，回读每个字段值与合计（如 合计未税金额），证明数据真进了表单模型而非只画在 DOM。

## 纯数据该长什么样（对业务用户）

- 只有业务字段名 + 业务值；**不出现** `#`、`selector`、`widget`（这些全在模板）。
- `values`：表头字段的一个扁平映射，字段名必须与模板 `field_map` 的 key 完全一致。
- `radio_selected`：要选中的 radio 标签列表（数组）。
- `detail_rows`：明细行数组，每个元素是一行的列名→值，列名必须与模板 `detail_columns.columns` 的 key 一致。

## 必填来源

- 表头必填：模板 `field_map[*].required === true`。
- 明细必填列：模板 `detail_columns.columns[*].required === true`。
- 校验器与引擎都读这两个结构化标记，不解析自由文本。

## 模板怎么新增一张单

新增一张 OA 单的模板时，先用受控 Chrome 实测真实页面，拿到字段 id / widget 名 / 必填标记，再按 `template-format.md` 落成模板 JSON。模板里标 `required` 的字段，就是校验器后续强制要求纯数据覆盖的范围。模板不含业务取值，不含凭据。

## 一个反例（不要这样做）

不要把页面 selector 写进用户要交的数据里。用户交的应当是可读的业务值；`scenario_id / selector / widget / text_contains` 是模板资产，由智能体持有。两者混在一个 JSON，等于让用户承担页面耦合 —— 违背三层契约。
