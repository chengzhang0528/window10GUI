# Where things live（资产清单）

> 从 `SKILL.md` 移出以满足热路径预算；规则与实测证据原文未改。


- Templates and pure-data schemas: `../../../src/DeskPilot.Flow/` (this skill's assets), co-located with the engine. See [template-format.md](template-format.md) for the exact schema.
- Engine (general, reads template + data, no business fields): `../../../src/DeskPilot.Flow/oa-fill-engine.mjs`. **Single entry (run this)**: `oa-run.mjs` — precheck → cleanup → login → open form → fill → gate 1–4 + timing, exit 0 only when all gates pass. **Regression runner**: `oa-regress.mjs` — runs every `data/*.data.json` scenario in one command and prints a pass/fail table (`--only <substr>` to filter, `--repeat N` for flaky triage, `--include-wip` to also run in-progress ones); exit 1 if any scenario fails. **Run it after changing the engine, a template, or any data file** — an unexercised data file silently rots (a long-unrun one was found carrying a wrong `经费` value and a form-disabled radio choice). **Naming convention**: a data file whose name starts with `wip-` is an **in-progress scenario that phase 2 has not finished**; the runner skips it by default so the suite keeps meaning "green = trustworthy". Never rename a scenario out of `wip-` to silence a red — that is how a gate stops being believed. Supporting general scripts: `oa-login.mjs` (portal navigation + login), `oa-open-form.mjs` (scripted 门户→流程→表单 entry), `close-stale-tabs.mjs`, `oa-data-validate.mjs` (offline pure-data validation). **Exploration (phases 1–2)**: `oa-explore-form.mjs` (field census), `oa-explore-options.mjs` (exhaustive option + linkage dump). **Phase gates**: `oa-gate.mjs` (mechanical gate check — use directly only to diagnose one gate). Result viewer: `show-fill-result.mjs`. Timeout baselines: `../../../src/DeskPilot.Flow/timeouts.mjs`. The older `fill-purchase-requisition.mjs` is a pre-generalization reference, not the path.
- Pure-data production and mapping method: [data-mapping.md](data-mapping.md).
- **Fast path for a whole pass — `scripts/wf-run-eval.mjs --seq <steps.json>`**: one CLI process for the entire
  pipeline (measured: a full pass — open form, main fields, three selects, two picker dialogs, add+fill two detail
  rows, four more picker dialogs, flicker probe, screenshot — in **42–50 s**, vs roughly 3–4 min when each step
  spawns its own CLI). Steps are data: `openform` / `find` / `attach` / `script` / `eval` / `click` / `wait` /
  **`openmodal`** / `flick` / `shot`. Use `openmodal` (not `click`) for every magnifier: it clicks, **polls** for the
  modal, verifies the **title**, retries, and warns when a modal was already open. Two measured traps:
  a picker can open **later than 2.8 s**, and a modal from the *previous* step may still be open — clicking the wrong
  modal is survivable (a row click writes to **that modal's own field**) but your verification will read as empty,
  so check the title.
- **`openform` must prefer a target that did not exist before the click.** Taking "the first rendered `static4form`"
  silently refilled an **old** instance and appended a stray detail row (measured). `wf-run-eval.mjs` now diffs the
  target set across the click and prints `NO_FRESH_FORM` instead of quietly reusing a dirty instance. And a genuinely
  fresh instance's detail table starts at **0 rows**, so add rows with `until: N` — "add one row" yields 1 or 2 rows
  depending on the starting point, i.e. it is not reproducible.
- **Mechanism A assets (in this skill, no per-form template)**: `scripts/wf-explore-components.js` (census + component classification + ambiguity/rendered flags), `scripts/wf-fill-by-component.js` (per-component dispatch with read-back; refuses `browser` hard-writes), `scripts/wf-interactive.js` (the split modes for selects and browser dialogs), `scripts/wf-run-eval.mjs` (**run the above from Node over the public CLI** — `readFileSync` + `JSON.stringify` so the file on disk is what runs, plus `--flick/--click/--wait/--shot/--eval` so the async-render orchestration is scriptable and the flicker measurement is reproducible), `wf-component-catalog.json` (component catalogue, classification order and the hard rules), `wf-validation.md` (the measurements behind every rule above). The `.js` files are injected as `chrome.evaluate` expressions — the host sets `window.__OA_FILL__` / `window.__OA_IT__` first; do **not** hand-copy their text into tool parameters (that is how it gets corrupted, and PowerShell's ASI/scope traps make it worse).
- **Report identity is load-bearing**: every census/options report must record the form it came from (`url` containing `workflowid=`). `oa-run.mjs` uses that to claim the right report and refuses one belonging to a different form. Two forms can share a filename prefix (`uih02` is both the loan form 2254 and the travel form 2211), so **never resolve reports by filename prefix alone**. Older reports predating this have `url: null`; they are used only when nothing better exists, aligned by the naming of the side that *is* verifiable.
- **Template self-check**: `oa-template-check.mjs --template <t> --census <.explore-*.json>` — verifies every hard-coded `#fieldNNNNN` in a template actually exists in that form's census. Build it into onboarding a variant: a copied selector that does not exist produces a **false failure** (the dialog pick succeeds, but the engine reads back through the wrong selector and reports `NOT_FILLED(空)`). It first compares `workflowid` on both sides and refuses with exit 2 when the census is of a **different form** — that mistake is easy to make because `oa-open-form` can leave the census attached to a stale tab. Exit 0 pass / 1 bad id / 2 wrong form.
