## 10. "重新打开页面并重填 + 尽快完成"（2026-10-08 17:2x）

### 10.1 先把"每次一步"变成"一条流水线"

新增 `wf-run-eval.mjs --seq <steps.json>`：**一个 CLI 进程跑完整条 pass**，步骤是数据
（`openform` / `find` / `attach` / `script` / `eval` / `click` / `wait` / **`openmodal`** / `flick` / `shot`）。

| | 每步各起一次 CLI | `--seq` 一条流水线 |
|---|---|---|
| 整条 pass（开单 → 主表 → 3 下拉 → 2 弹框 → 加/填 2 明细行 → 4 弹框 → 频闪 → 截图） | 约 3~4 分钟 | **42~50 秒** |

### 10.2 第一跑就暴露了 `openform` 的**真缺陷**

它报 `form=F5CE8144…`，但那是**旧表单**（`countBefore:2` 证明它本来就有 2 行）——
我的实现取了"第一个已渲染的 static4form"，于是在**脏实例上重填、还多加了第 3 行**。
而 `chrome.targets` 显示**点击其实开出了新标签页 `0474CA81…`**，只是被我忽略了。
**修复**：点击前快照 target 集合，点击后**优先选新出现的 target**；没有新的就明确报
`NO_FRESH_FORM`，绝不悄悄回退。旧表单多出的空行用 `delDetailRow('detail_1','2')` 清掉（3→2）。

### 10.3 第二跑：真干净实例（并发现明细起始行数是 0）

先**自检**再填：`{rows:0, cglx:'', xmh:'', lcck:'', sqyy:'', cgxqsm:''}` —— 确实是干净实例。

- 主表：`filled:6 ok:6`；三个下拉用**已实测 optionValue** 直写，全部 `ok:true`（采购类型 0 / 签批跳转 3 / 是否含培训费 0）
- 项目号：`SAP_项目号` 10 行 → `100110000001`
- 工厂：`changeFieldAttr(view:0)` → 触发按钮 **16×28** → `SAP工厂` 8 行 → `1201`
- 明细：`countBefore:0` → 加一行 → **1**。⇒ **干净实例的明细起始行数是 0，不是 1**
  （此前看到 1 行是因为联动已经建了一行）。于是"固定加一行"在 0 行/1 行两种起点上分别得到 1 行/2 行，
  **不可复现** —— 已把加行改成幂等的 `until: N`。
- 因此第 2 行的填列与弹框全部 `CHROME_ELEMENT_NOT_FOUND`（`_1` 字段还不存在）——如实失败，不是"静默跳过"。

### 10.4 第三跑与第四跑：把第 2 行补齐，并发现"弹框会迟到"

- `until:2` → 1→**2** 行；第 2 行 `ok=10 fail=0`，`wszj=16000.00`（5×3200 ✓）
- 但第 2 行的两个放大镜 `click ok=true` 而 2.8s 后**没有可见弹框** ⇒ 判定为"没开"是**错的**
- 第四跑用新的 `openmodal`（点击 → 轮询 → 复核标题 → 重试）时看到：
  `try1 click=true modal_open=true rows=10 title=SAP采购订单` —— **进入该步时已有一个弹框开着**，
  正是上一跑那次点击**迟到才开出来的**。所以真相是**弹框开得比 2.8s 更慢**，不是点击丢失。
- 附带确认：**弹框的行点击写回该弹框自己的绑定字段**，所以"点错弹框"不会写错字段
  （最终两列都对）；但**回读会显示为空**，因此必须核对弹框标题。
