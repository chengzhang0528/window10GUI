## Trigger

用户明确要求对已有工作空间或候选独立执行集成测试、系统测试、全量测试、候选验收、发布门禁或回归，并以测试结论作为本任务主要结果。CI 配置、发布门禁、测试工具、环境、覆盖规模或 Development 完成本身不创建该任务。

## Input

用户明确测试目标、被测工作空间或 Candidate、Environment、测试范围、进入/退出条件、稳定 Runbook 和明确不测试项；受控 SystemTest 还需要请求来源，持久受控 SystemTest 才需要任务入口和 SystemTestPlan。

## Output

仅针对实际被测工作空间或 Candidate 及 Environment 的通过、失败或受阻结论、断言证据和缺陷清单；受控候选测试可以产生供用户决定是否另建 Deployment 的准入证据，但不产生产品源码修复或部署结果。

## Actions

常规或临时受控 SystemTest 执行 `ACT-CLASSIFY-REQUEST` → `ACT-CLASSIFY-EXECUTION-TYPE` → `ACT-ROUTE-CONTEXT` → `ACT-VERIFY-BASELINE` → `ACT-RUN-SYSTEM-TEST` → `ACT-VERIFY-RESULT` → WF-0004；受控时在当前任务工作计划中固定请求来源、Candidate、Environment、进入/退出条件。

持久受控 SystemTest 在路由后调用 `ACT-REGISTER-TASK` 和 `ACT-OPEN-SYSTEM-TEST-PLAN`。持续环境阻断使用 `ACT-CAPTURE-BLOCKER`；发现产品或测试实现缺陷、新需求时只记录，获得用户修复授权后另建 WF-0002。

## Key Constraints

- SystemTest 先分别判定控制强度和持久化需求。临时测试不登记任务或计划；受控测试无论是否持久化都必须记录用户请求来源并固定 Candidate 和 Environment，持久测试再保存为任务和 SystemTestPlan。
- 被测源码和制品在测试期间只读。断言失败或发现新需求不得在本任务中顺手修改；记录最小复现或需求并建立独立 Development 任务。项目和会话不存在“切回开发”状态。
- 环境、凭据、启动、迁移或 fixture 失败与产品断言失败分开报告；前者表示证据不可用，不得伪造产品失败。
- 可以按 Runbook 准备隔离测试环境，但不得发布到正式目标、推送正式制品或执行生产迁移。
- 测试通过不创建或执行 Deployment 任务；只有受控候选测试才可形成部署准入证据。

## Stop When

用户没有明确要求独立测试，或被测内容、环境、范围无法确定时停止。持久受控测试在计划仍为 Draft 时停止；任一测试需要修改产品源码、缺少必要权限/秘密、环境状态不可隔离，或继续会进入部署时停止。
