Kind: Workflow
Workflow ID: WF-0002

Scope: coder_driver-template / 功能开发、Bug 修复与技术迁移
Owner: 项目维护者
Updated: 2026-08-08
Depends On:
- WORKFLOW_CONTRACT.md
- ../../.agents/skills/technical-solution/SKILL.md

## Trigger

用户以交付功能、修复 Bug、实现新需求、设计、重构或治理为本任务目标，并授权修改源码、数据、API、构建、测试、技术执行逻辑或治理校验代码，或者任务需要编码级技术方案才能安全推进。

## Input

本次 Development 任务、已验证的当前态 A、授权边界、成功标准、停止条件，以及风险实际命中的长期事实所有者和专业 skill。

## Output

授权范围内的实现增量、范围匹配的白盒证据、验证后的目标态 B、实际必要的长期事实更新，以及由 WF-0004 形成的 Development 结果；持久受控变更还必须与 Active ChangePlan 一致。可选输出确定候选版本，但不自动进入 SystemTest。

## Actions

常规变更执行 `ACT-CLASSIFY-REQUEST` → `ACT-CLASSIFY-EXECUTION-TYPE` → `ACT-ROUTE-CONTEXT` → `ACT-VERIFY-BASELINE` → `ACT-EXECUTE-CHANGE` → `ACT-VERIFY-RESULT` → WF-0004。

临时受控变更执行相同 Action，但在当前任务工作计划中先明确 A→B、约束、成功标准和停止条件，不调用 `ACT-REGISTER-TASK` 或 `ACT-OPEN-PLAN`。持久受控变更增加 `ACT-REGISTER-TASK`，并在执行前调用 `ACT-OPEN-PLAN`。出现持续阻断时调用 `ACT-CAPTURE-BLOCKER` 并进入 WF-0003。

## Key Constraints

- 常规变更必须满足 `WORKFLOW_CONTRACT.md` 的全部常规条件和定向事实发现门禁；不登记任务、不创建 ChangePlan，也不为收口读取或改写无关长期文档。
- 受控变更都必须先有可核验工作计划；只有持久受控变更将它保存为 `Workflow: WF-0002` 的 Active ChangePlan。
- 功能开发和 Bug 修复任务只执行范围匹配的白盒检查与定向验证；不得因为代码完成、提高信心、收口、测试形式或存在测试入口而自行追加独立集成、系统或全量测试。
- 单元、组件、契约、局部集成、真实库、浏览器或受管服务检查，只要用于直接证明当前改动且范围匹配，均可作为 Development 证据；用户把它们列为实现或修复的验收要求时仍属于同一 Development 任务。只有用户要求对已有工作空间或候选独立形成测试结论时才进入 WF-0005，并按治理强度决定是否建任务。
- 不发布正式包、不执行目标环境迁移、上线、切换或回滚；这些动作必须另建 WF-0006 任务。Git commit/push 不是 Deployment。
- 不扩张服务、权限、产品边界或外部依赖，超出授权时停止。
- ProductContract、CurrentDesign、Decision、Runbook 和 skill 只在定向发现命中或对应长期事实发生变化时加载、更新；不得把每次代码修改都写成长期事实。
- 常规变更实施中一旦发现公共契约变化、消费者无法可靠枚举或不可恢复状态等风险，停止编码并转为受控变更；只有同时出现恢复需求时才登记任务和方案。

## Stop When

基线无法验证、关键选择未决、需要新权限或秘密、方案范围不足、白盒验证失败，或继续执行会进入用户未授权的 SystemTest、Deployment 或其他工作时停止。
