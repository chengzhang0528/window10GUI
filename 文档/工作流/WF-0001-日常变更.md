# WF-0001 日常变更

Status: Active
Kind: Workflow
Workflow ID: WF-0001
Phase: Development
Scope: coder_driver-template / 非编码工作空间变更
Owner: 项目维护者
Updated: 2026-08-08
Depends On:
- WORKFLOW_CONTRACT.md

## Trigger

用户要求修改正式文档、任务控制或治理配置，且不需要改变 业务源码、数据、API、构建或技术执行逻辑。

## Input

用户目标、当前工作区状态、命中的正式文档所有者、可观察验收标准，以及仅在需要持久恢复时存在的任务入口。

## Output

授权范围内的最小工作空间增量、匹配的文档验证证据，以及由 WF-0004 形成的完成、取消或未完成状态。

## Actions

常规或临时受控变更执行 `ACT-CLASSIFY-REQUEST` → `ACT-CLASSIFY-EXECUTION-TYPE` → `ACT-ROUTE-CONTEXT` → `ACT-VERIFY-BASELINE` → `ACT-EXECUTE-CHANGE` → `ACT-VERIFY-RESULT` → WF-0004。

需要持久恢复的受控文档变更在路由前增加 `ACT-REGISTER-TASK`；同回合可完成且没有恢复状态时不登记。

## Key Constraints

- 不创建 ChangePlan，除非调查表明任务实际需要编码或技术迁移；此时转换到 WF-0002。
- 控制强度和持久化需求分别由 WorkflowContract 判定；受控文档变更不因受控自动登记，同回合任务用当前工作计划执行门禁。
- 只修改拥有本次事实的唯一文档，不顺带整理其他内容。
- 正式文档或治理入口发生变化时执行 `ACT-VALIDATE-DOCS`；没有文档增量时不运行文档检查。
- 本 Workflow 只处理用户要求的 Development 文档任务；文档涉及测试或部署主题不等于用户另行授权 SystemTest 或 Deployment。

## Stop When

需要修改应用源码、改变产品/安全边界、无法确定唯一事实所有者，或用户目标与当前规范冲突时停止并重新分类或确认。
