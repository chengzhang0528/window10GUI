# WF-0004 任务收口

Status: Active
Kind: Workflow
Workflow ID: WF-0004
Scope: coder_driver-template / 完成、取消与未完成收口
Owner: 项目维护者
Updated: 2026-08-08
Depends On:
- WORKFLOW_CONTRACT.md

## Trigger

任一会改变工作空间的任务准备报告完成、取消，或者当前回合结束但任务仍受阻。

## Input

本次任务类型、任务、工作空间或外部环境增量和验收结果，以及仅在实际存在时提供的 ChangePlan/SystemTestPlan/DeploymentPlan/Issue、长期事实所有者和文档验证状态。

## Output

本次任务的三种互斥结果之一：完成并清理活动入口；取消且准确保留或清除已生效事实；未完成并保留可恢复入口。只有同一请求明确建立其他任务时才分别报告其状态；Git 状态独立报告。最终汇报必须让用户能核验任务类型、变更、证据、文档迁移和仓库状态。

## Actions

始终执行 `ACT-VERIFY-RESULT` 和 `ACT-REPORT-RESULT`。只有存在长期事实增量或有可靠依据的独立未承诺结果时才执行 `ACT-CLASSIFY-KNOWLEDGE` 和 `ACT-RECONCILE-KNOWLEDGE`；只有存在任务或活动文档时才执行 `ACT-RESOLVE-ACTIVITY`；只有正式文档或入口发生变化时才执行 `ACT-VALIDATE-DOCS`；只有已登记任务的结果会影响后续选择时才执行 `ACT-ARCHIVE-RESULT`。

## Key Constraints

- 用户要求已实现且范围匹配的白盒验证未发现问题时，功能结果为完成；存在活动文档或任务时，文档门禁也必须通过，才能删除 ChangePlan、移除 TASK_CONTROL 项。
- 未被用户要求或未建立的 SystemTest、Deployment 不属于 Development 的“后续未执行阶段”，也不进入默认汇报。开发任务已执行证据若确认本次缺陷则不得通过。
- 临时 SystemTest 对当前任务固定的工作空间或 Candidate 和 Environment 形成结论，持久 SystemTest 对计划绑定的 Candidate 和 Environment 形成结论；Deployment 只对绑定 Artifact 和 Target 形成结论。任一任务完成都不得自动创建、执行或宣称另一类型任务完成。
- 用户明确要求多个任务类型时，先收口或阻断当前任务，再按治理强度建立下一任务；不得把 ChangePlan、SystemTestPlan 或 DeploymentPlan 改绑到另一个 Workflow 继续使用。SystemTest 或 Deployment 发现 Bug、新需求或测试实现缺陷时只记录，获得用户修复授权后才另建 Development 任务，不写成全局阶段切换。
- Git 未暂存、未提交、未推送、同步失败或并行文件归属冲突只记录为仓库状态；不得因此反转本次任务结论，也不得仅为等待 Git 收口保留任务或任何活动文档。
- 没有长期增量时输出明确判定，不创建占位文档；有已生效事实时不能以取消规避迁移。
- 未完成时保留唯一任务入口、必要活动文档和下一可执行条件，不写虚假完成事实。
- 临时执行没有任务或活动文档；验证后直接报告，不补建任务或归档。只有长期事实或候选清单实际变化时才更新对应文档。
- 只有证据支持一个独立、可验收、未承诺结果时才更新 `WORK_CANDIDATES.md`；候选不携带执行类型，不自动建任务。当前用户明确发起的同一结果必须从候选清单移除，用户纠正同一结果时更新原项。

## Stop When

本次任务的实现或操作未完成、其必需证据失败、实际存在的长期事实未归位、已触发的引用校验失败或用户明确要求的本任务验收不完整时停止完成收口。未被要求的其他任务类型或 Git 阻断不得反转已经形成的任务结论。
