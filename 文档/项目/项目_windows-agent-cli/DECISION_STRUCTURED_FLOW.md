## 结果与设计决策

本决策定义有复用价值时保存和重放的纯数据流程。首次任务默认由 Agent 观察页面、连续执行已知动作，并按结果选择下一批次，方法由 [场景进化 Skill](../../../.agents/skills/deskpilot-flow-evolution/SKILL.md) 拥有；无需先完成此数据编排。选择结构化复用后，通用执行器执行动作、检查结果，偏离预期时主动返回异常。XRain 演示站是场景对象，场景不授权修改或重新部署 XRain。实际入口和字段由 [宿主说明](../../../src/DeskPilot.Flow/README.md) 定义，代码支持范围由当前设计记录。

| 决策 | 实现责任 | 用户与 Agent 的入口 | 持久化影响 |
|---|---|---|---|
| 场景是可阅读、局部修改的纯数据 | JSON 定义目标、动作、输入、完整判据、等待与依赖；通用执行器解释 | 同一份流程文件，同时包含意图标签与机器字段 | 保存流程及 revision，无场景函数模块 |
| 每一步主动判断结果 | 执行器检查前置、后置、依赖与最终状态 | 正常进度和异常详情来自同一事件源 | 状态默认内存 |
| 成熟流程重放时 Agent 处理偏差 | worker 停止执行，supervisor 向调用方返回 handoff | Agent 收到最小异常包，观察后选择直接操作或安全的新 run | 不新建通知服务或模型调度平台 |
| CLI 维持通用执行职责 | 复用公开 NDJSON 方法、观察与生命周期 | 数据字段经宿主转换后调用 CLI | 不改变 CLI 协议，不加入网站业务规则 |

场景文件不能通过 .mjs 导出对象，也不能把关键判据藏在 handler、脚本路径、表达式或回调里。命名检查可以复用，但其全部条件必须在同一份数据中可见。执行器的 .mjs 是共享程序实现，不是用户和 Agent 需要逐场景编写的资产。

当前采用 JSON，以便直接解析且不增加格式依赖。它是有限的执行数据契约，不包含通用编程控制流；不提供任意 JavaScript 逃生口。已有原语无法表达业务结果时，显式报告能力缺口，再完善通用读取或比较能力，不能新增网站专属执行函数掩盖缺口。

## 数据如何表达操作与成功

流程的固定身份、版本和输入与有序步骤分开。定位定义表达可复用目标，检查定义表达明确的属性比较；步骤引用这些数据。Agent 修改某个定位、等待或判据时，不必重新编写执行器。具体支持字段以宿主 README 和解析器为准，未知字段在启动桌面执行前拒绝。

| 信息 | 数据必须表达的内容 | 执行语义 |
|---|---|---|
| 目标 | CSS 定位及必要文本限定 | 使用前重新查找；应唯一的目标歧义时失败，不静默取第一个 |
| 输入 | 可复用参数与明确输入引用 | 作为值解析，不当作代码执行 |
| 动作 | 已支持的有限操作及参数 | 通用实现通过 DeskPilot 执行，场景不持有浏览器客户端 |
| 检查 | 目标、属性、比较关系和期望值 | 程序读取当前状态后计算 pass/fail/unknown |
| requires | 动作前需要成立的检查 | 不满足时不派发动作 |
| consumes | 前序 step_id.check_id | 重跑原判据，不能只相信历史 succeeded |
| expect | 非空的动作后检查列表 | 全部通过才发布本步成功和结果事实 |
| releases | 本步成功后不再保持的前序事实 | 只用于计划内状态变化，在本步成功前不生效 |
| min_delay_ms | 动作返回后的最小等待 | 时间经过不等于条件成立 |
| timeout_ms | 流程、步骤和检查预算 | 共用上层剩余预算，不在每个阶段重新计时 |
| poll_ms / stable_ms | 采样间隔和连续通过窗口 | fail/unknown 重置窗口；不承诺采样间隙绝对稳定 |
| final_checks | 完成前需要再次成立的结果事实 | 所有步骤成功仍须最终复核，才返回 completed |

例如“填写搜索条件”的成功定义必须直接表达“当前 URL 正确、搜索框唯一、value 等于 keyword、受控结果区域呈现预期状态”。仅写 searchFilled 或命令返回 ok 都不够。字段值、可见性、可操作性、元素数量、属性、页面地址或文本等检查由通用原语提供。

当前数据中的检查片段如下；search 是同文件 targets 中的定位定义，searchTerm 是 inputs 中的参数。完整场景还组合 URL 与结果区域判据：

```json
{
  "predicate": {
    "type": "element",
    "target": "search",
    "count": { "equals": 1 },
    "value": { "equals": { "input": "searchTerm" } }
  },
  "timeout_ms": 15000,
  "poll_ms": 200,
  "stable_ms": 200
}
```

“至少等待 200 ms 后找到表单再填写”应拆成等待后确认表单的步骤与消费该事实的填写步骤；填写之后继续读取实际值及所需结果。等待不是替代判据的固定 sleep。保存类动作必须验证对应记录的持久结果；仅有 toast 不足以证明保存。没有可观察判据时应交接，不制造成功条件。

## 执行、前序失效与反馈

1. 先解析并验证纯数据、输入、动作、检查引用和依赖顺序，再创建执行进程。固定本次 run_id、revision 与执行代次，不在运行中热改定义。
2. 建立执行 lease 和准确页面上下文。每步先检查取消与期限，重新验证 consumes，再验证 requires；全部通过才派发动作。
3. 动作返回后处理执行错误、登录暂停或结果不明；再等待 min_delay_ms，并在剩余预算内轮询 expect。检查读取失败是 unknown，不能通过。
4. 全部 expect 通过才发 step.succeeded、发布带来源的事实并处理 releases。底层动作确认与业务检查通过分开。
5. 必需检查失败或不可判定时抛出 StepFault，停止后续动作。全部步骤完成后重查 final_checks；最终检查失败仍返回 handoff。
6. 有界停止并清理旧执行者后返回终态；崩溃和超时由外层 supervisor 合成异常，不能要求已崩溃的脚本自行报告。

事实记录来源步骤、检查 ID、run/revision/generation、target_id、观察时间及必要期望/实际摘要。它证明过去的观察，不保证状态永久有效。业务对象和页面身份由数据判据明确检查，不能只用标签页 ID 替代。运行结果不保存跨会话有效的 DOM 引用或坐标。

例如填写曾通过，但之后输入被异步清空：提交步骤消费填写结果时重新读取，报告 PRIOR_RESULT_INVALIDATED，producer_step_id 指向填写步骤，detected_at 指向提交步骤，提交 action_dispatched=false。来源步骤不等于根因，缺少证据时 root_cause=null。

沿声明依赖向后推导 affected：已执行的依赖结果标为 needs_revalidation，未执行的依赖步骤标为 blocked。保留历史成功事实，不伪造当时失败，也不自动撤销已经发生的操作。正常跳转用 releases 释放旧页面事实，后续消费新页面结果。

检测发生在后置轮询、依赖消费和最终复核等检查边界，不是全时扫描历史。长流程需要更早发现问题时，应拆出有检查边界的短步骤。没有声明、无法观察的问题不能保证检出。

## 异常与接管协议

步骤状态与动作效果分开：步骤 pending/running/succeeded/failed/blocked/cancelled；effect 为 not_dispatched/dispatched/confirmed/unknown。失败可能已发生效果，未知效果不能重放。流程终态为 completed/handoff/cancelled，用户取消不自动变成修复请求。

| 异常 | 意义与脚本响应 |
|---|---|
| FLOW_INVALID | 数据或引用不支持，桌面 0 动作，交接定义错误 |
| PRECONDITION_FAILED / POSTCONDITION_FAILED | 当前前置或后置条件不成立，附检测位置和必要比较结果 |
| PRIOR_RESULT_INVALIDATED | 旧结果复核不成立，附来源、发现位置和受影响步骤 |
| CHECK_UNAVAILABLE | 状态无法读取或上下文失配，保持 unknown，不冒充业务错误 |
| ACTION_FAILED | 原语失败，保留底层错误；已派发未确认的效果保持 unknown |
| DEADLINE_EXCEEDED / EXECUTOR_LOST | 预算耗尽或执行进程失联，由存活宿主主动合成异常 |
| USER_ATTENTION_REQUIRED | 登录或挑战阻止继续，保留暂停边界 |

异常包包含 flow/run/revision、当前步骤、fault.code/phase、producer_step_id、expected/actual 必要摘要、已完成步骤、affected、effect、quiescent 和恢复要求。通常只需布尔比较、数量和相关目标身份，不返回完整页面或客户记录；秘密不写入场景或日志。

handoff 前停止派发并有界取消旧请求。仅在确认旧执行者退出后 quiescent=true；取消未确认或执行树失联时保持 false，另一个 Agent 不得继续 GUI 写入。杀进程请求成功本身不证明已发送的业务效果未发生。

同一事件源输出 step.started、step.dispatched、step.succeeded 与终态。用户可看标签、进度和原因；Agent 单次调用执行整段正常流程，只在终态或异常时判断。stdout 不会自行唤醒休眠模型；自动投递由已有调用宿主负责，不在 CLI 内运行 Agent。

## Agent 修订与复用

Agent 收到异常后先确认执行权和当前状态，区分网站缺陷、定位变化、等待不足、会话问题及执行器能力错误。根据新观察直接执行剩余安全动作；需要更新可复用流程时才调整数据并增加 revision，不降低业务断言换取通过。Skill 只保留通用方法；需要沉淀的网址、选择器和业务判据留在流程数据中。

当前继续方式是 Agent 决策后的新 run，不支持任意跳到某步或持久断点恢复。页面、输入或定义变化后重新建立依赖；只在重放已知安全时重跑，否则构造带新前置条件的局部恢复流程。对未知副作用先读取确认，无法确认就保留未完成，不能盲目重新提交。

已明确授权的演示快捷登录可通过 DeskPilot 完成；真实密码、OTP 或挑战不因此获得绕过权限。网站产品缺陷仅报告，不擅自修改或部署目标网站。

## 本次完成与验证边界

纯数据入口、业务判据可见、未知代码字段拒绝、依赖失效主动停止是代码完成条件。JSON 只是表达方式；场景成熟度仍需观察完成率、Agent 介入、耗时和实际 Token 证据。宿主 intermediate_model_calls=0 仅说明正常执行内部不调用模型，不等于探索或接管没有 Token 消耗。

定向验证覆盖数据解析和比较、错误输入零动作、后置失败、前序失效、稳定窗口、执行进程失联和清理。真实网站由 Luna 子代理使用 DeskPilot 复跑总览、搜索与复位、对象字段页，以及未提交输入变更触发的前序失效和安全复跑；空记录场景只证明输入与空状态变化，不能代表有数据的筛选正确性。

长流程样例见 [56 步父子对象闭环](../../../src/DeskPilot.Flow/README.md#父子对象的-56-步闭环)：创建、修改、离开后回读、先子后父删除及重新加载确认清理。Luna 使用 DeskPilot 完成两次 56/56 步回放；保存前故意改变编码，依赖复核返回 PRIOR_RESULT_INVALIDATED，保存未派发。首次取消删除遇到隐藏弹层残留，修订 JSON 定位并以核对精确记录身份的局部恢复流程清理，未修改执行器或 XRain。两次成功不代表长期无人值守稳定率已测定。

出现无法确认的页面身份、无可观察的关键结果、旧执行者未退出、未知业务效果或超出授权的操作时停止自动执行并报告。独立系统测试与部署不从本次 Development 完成自动启动。
